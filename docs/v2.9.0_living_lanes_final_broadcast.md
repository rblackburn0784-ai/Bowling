# Gutter Saints Bowling — v2.9.0 Living Lanes 2.0 & Final Broadcast

**Base:** v2.8.5t `main` commit `14eb6626e595fe7a36cfe5a9a319b2c09cdab0ff`.

**Status:** packaged feature build, **not** production certified. No GitHub changes are made when this archive is built.

## What changed

### 1. Impact-driven tenpin simulation

- Introduces `services/impact_model.py`, a deterministic **physics-informed** arcade model, not a literal 3-D rigid-body collision engine.
- Every delivery now estimates a lateral point of pin-deck impact from release miss, effective hook, handedness, ball type, lane oil, transition, wear and board adjustment.
- Bowling-ball speed, revolutions and entry angle factor into carry and strike probability, with front-to-back pin-to-pin transfer rather than uniformly independent hits.
- Spare attempts choose the nearest reachable **standing** pin; left/right handed split targeting is mirrored. A gutter then full rack on ball two remains a **spare attempt**, not a strike.
- Impact events include `impact_x`, `pocket_x`, `oil_bias`, `line_correction`, `carry_factor`, `contact_order` and other metrics. No scoring, frame bonus, or pin-numbering convention has changed.
- `release_metrics` reflects carrydown and selected lane zones/board moves, instead of reporting hook/entry wholly independently of lane wear.
- Existing player-assigned stats, rank growth, ball selections, shot intents, lane pair switching, game persistence and tournament logic remain intact.

### 2. Single authoritative pinfall timeline across all cameras

- The left hero lane, overhead camera and front pit camera now apply the **same per-pin contact order** from the game event during the five impact steps, and share the same `before`, `down`, `after` sets.
- The ball sprite's displayed impact endpoint is tied to the simulated `impact_x` when available; legacy event paths retain their former projection.
- The simpler fallback lane animation now uses the same impact order rather than a numeric pin sort.
- No changes to 941×1672 left hero canvas, 1254×1254 cameras, scale, three-panel broadcast layout, existing bowler sprite sequence, or shot animation timing; v2.8.5t 4–3–2–1 overhead correction remains in place.
- Rendering consumes **no gameplay RNG**. The scene renderer may be safely re-run without altering scoring outcomes.

### 3. Safe upgrades with old active matches

- New sessions store `physics_version='2.9.0'` in snapshots.
- Prior snapshots missing that field resume under a frozen `2.8.5t` engine (`services/legacy_v285t_pin_engine.py`). This preserves the old probability rules and RNG consumption when a match is resumed after updating.
- Existing database storage is unchanged; migrations from v2.8.5t still apply.
- Do not remove the frozen compatibility engine until all old match histories are retired.

## Installation / upgrading

1. Back up `data/gutter_saints.db` and the existing `assets/` artwork and sound folders.
2. Stop the running Discord bot and extract the new source **without deleting** its `data/` directory.
3. Preserve your original PNG assets at unchanged paths (listed below).
4. Install dependencies with `python -m pip install -r requirements.txt`.
5. Run `python -m unittest discover -s tests -p 'test_*.py' -v` and `python -m services.release_audit`.
6. Run `python -m services.v290_audit` to verify the rules (no artwork or Discord connection required).
7. Set `REQUIRE_PRODUCTION_ART=1` to block staging startup if artwork is missing; run a full new game and restore an in-progress v2.8.5t game.

**Required media:** `assets/lane/gutter_saints_empty.png` (941×1672); `assets/cameras/overhead_empty.png` and `assets/cameras/pit_empty.png` (both 1254×1254); `assets/pins/overhead`, `assets/pins/vertical`, `assets/sprites/the_dude`, `assets/sprites/jesus`, and ten matching ball PNGs under `assets/balls`.

**Known limitations / release gates:**

- Physics are tuned for balanced Discord arcade gameplay, not certified tenpin laboratory simulation. Additional live tournament balance testing recommended.
- The historic 5–3–2 locator marks on older overhead images are corrected *in memory* using a heuristic; a clean regulation 4–3–2–1 overhead plate is still preferable.
- Live mobile/desktop GIF playback timing, actual sprite placements and Discord rate limits have not been exercised with production art in this environment.
- Do not switch an **in-progress match** deliberately from legacy to v2.9 physics. New games use v2.9 automatically.
- v2.9.1 presentation features and v2.9.2 career/competition polish remain later roadmap items, not part of this build.

## Suggested staged acceptance

- First ball / second-ball spare / split / 10th bonus ball across right and left handers: same pins in all camera views and same standing pins on the scoreboard.
- At least one pre-v2.9 snapshot recovers successfully without changing its physics version.
- Tournament score, career XP, standings and round advancement stay idempotent after restoration.
- Actual art displays a 4–3–2–1 overhead rack and correct 941×1672 hero/pit placement on Android and desktop Discord.
