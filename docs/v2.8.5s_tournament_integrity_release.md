# v2.8.5s — Tournament Integrity, Recovery & Reliability

## Seven audit corrections

1. **Restored friendly challenges remain friendly.** The snapshot now preserves `friendly_challenge`, stable session UID, and last-delivery metadata. Exhibitions remain excluded from ranked records, progression, achievements and attribute growth on restore/undo. Friendly daily non-ranking XP behaviour remains unchanged.
2. **Tournament ties resolve to a winner.** Single-elimination tied totals trigger a deterministic, one-ball-per-team sudden-death roll-off on fresh racks, repeating tied rounds until a winner. Representatives are the highest-game scorers on each team. Roll-off pinfall does **not** alter the ten standard frame scores or ranked career statistics. The match stores `rolloff_json` for audit and advances the bracket transactionally. Unlike tenpin scoring, this roll-off is a **Gutter Saints tournament policy**, not a modification of regulation frame scoring.
3. **Tournament Director interactions are permission-gated.** All DirectorView controls, the Presentation modal, and command entry are checked for Manage Server or Administrator permission at interaction time rather than relying on slash-command defaults.
4. **An existing channel match cannot be silently overwritten.** `/game_start`, exhibition setup, friendly accepts, competition UI fixture launch and `/fixture_start` now reject live or recoverable sessions. Each match saves an initial recoverable checkpoint before its first ball; new sessions purge stale snapshot history only after the guard succeeds.
5. **Undo Last Ball removes exactly one delivery.** Undo uses the last `pre_ball` checkpoint (not the immediately preceding arbitrary snapshot) and removes both pre/post records of that delivery. Career tendency evidence, attribute changes, and delivery timelines are restored to their preceding checkpoint. An optimistic comparison refuses rollback if another match has since changed the bowler's career. Undo is also blocked while a delivery runs and after a game has been recorded, and rebuilt controls are posted after restore/undo.
6. **Completion safely survives an interrupted database write or Discord send.** Base result rows use a persistent `session_uid` to prevent duplicate games, then history, season totals, XP, rank, tendencies, achievements and tournament updates are committed in **one SQLite transaction**, marked by `game_finalizations`. A failure rolls back the entire second phase; retries cannot double-count. The Restore Match action can finish an interrupted completed session and clear stale state if it was already committed.
7. **Full-rack spare attempts use spare logic.** A second ball after a gutter, or third ball following `X-`, cannot go through the first-ball strike chance and strike-carry tag code merely because all ten pins remain standing. Spare scoring and rack display use the pre-existing engine rules.

## Visual preservation

No changes to `services/scene_renderer.py`, `services/broadcast_layout.py`, `services/shot_animation.py`, `services/lane_visual.py`, `services/bowler_sprites.py`, `services/ball_sprites.py`, the media asset paths, sprite scale/position, hybrid broadcast proportions or GIF timing. Changes in `cogs/games.py` are limited to game-flow safeguards, permissions and persistence/finalisation. The image files omitted from the user's v2.8.5r source ZIP remain omitted; retain the existing lane, overhead, pit, character, ball and pin assets in the installation.

Install `requirements.txt` and run `python -m unittest discover -s tests -v` to execute the complete suite including Discord tests.

## Upgrade and recovery notes

- **Make a backup of `data/gutter_saints.db`** before replacing the code. Automatic schema migrations add `games.session_uid`, `match_snapshots.career_json`, `tournament_matches.rolloff_json` and the `game_finalizations` ledger. Existing rows are preserved.
- Existing *in-progress* 2.8.5r snapshots lack the new per-ball career checkpoints. They can be restored, but Undo may not be able to reverse career evidence from balls thrown on the prior version. For reliable results, start a fresh match after upgrade.
- **Pre-upgrade half-finalised games are not automatically repaired.** Older completed games never had stable session IDs or the completion ledger, so they may require manual reconciliation. The new idempotent path covers new v2.8.5s games.
- Discord attachment rendering, interaction permission behaviour, and image accuracy should be smoke-tested in the target server with `discord.py` and local assets; the artifact-generation environment did not have access to that dependency.
