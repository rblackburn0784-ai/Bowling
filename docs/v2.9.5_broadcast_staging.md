# v2.9.5 — Broadcast Studio (staging)

This GitHub branch contains the Python broadcast logic for v2.9.5 plus the prior v2.9.4 match-final presentation fix. It is **not a complete or approved release**.

## Changes staged
- One primary GIF per real delivery, rendered without a second engine call.
- Optional read-only slow-motion replay of the recorded event, followed by restoration of the static leave.
- Replay-selection policy for strikes, splits and difficult spares.
- v2.9.4 match-finishing support for exhibitions and tournaments.
- New standalone policy regression tests.

## Not uploaded to GitHub
The full local v2.9.5 archive includes revised `services/showtime_graphics.py` and these binary 1672×941 / 1254×1254 PNG assets:
`assets/scoreboards/start.png`, `assets/scoreboards/end.png`, `assets/cameras/overhead_empty.png`, `assets/cameras/pit_empty.png`, `assets/lane/gutter_saints_empty.png`.

**Do not merge** this staging branch as a full v2.9.5 build until those files are supplied and their live positioning, replay playback and scoring-isolation tests pass. This connector cannot read binary bytes from a local ZIP for GitHub blob uploads.

## Known caveats
- GIF playback is client-controlled; a second intentional replay may follow a strike. It must never call `session.bowl()`.
- The full v2.9.5 local overlay includes additional installer tests and artwork that are not present in this staging branch.
- Replays add deliberate latency, so test full matches for pacing and Discord rate limits.
