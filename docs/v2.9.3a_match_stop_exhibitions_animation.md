# v2.9.3a — Match Stop, Admin Exhibition Safety & Single-Play Animation

## Fixes

1. **Stop/Cancel Game**: Administrators can use the 🛑 **Stop Game** button on the public match controls, the Admin → Match dashboard, or `/game_stop`. All require Manage Server/Administrator permission and a second explicit confirmation. A running Auto Play completes only the current visual delivery; it will **not bowl another ball**. The unfinished result is discarded, relevant attribute growth is unwound in one SQLite transaction, and a playing fixture returns to **scheduled**. Stop never alters a *committed* match, awards, standings or history. Use match-result correction for a finished game. A conflicting external career update blocks cancellation for safety.
2. **Admin-started games are unranked**: Both Admin → Start Match and `/game_start` now create an **Unranked Exhibition / Practice**. Neither rank XP, career stat growth, career history, achievements, tournament standings nor cosmetic exhibition XP is awarded. The mode is stored in recovery snapshots. Actual competition fixtures and tournaments remain ranked and use their original pathways. Player-created friendly challenges continue their existing optional daily cosmetic XP behaviour.
3. **Animation plays once per delivery**: The existing GIF had no looping extension and only one GIF was produced for each `GameSession.bowl()` call, but Discord could display it long enough to replay. The extra display headroom is reduced from 1.5 seconds to 0.30 seconds, and the GIF is replaced with a settled still at the end of each delivery. The **23-frame 2.795-second GIF sequence, physics, scoring, camera geometry and animation poses remain unchanged**. Actual client autoplay behaviour can vary; confirm this in Discord mobile and desktop staging.

## Caution with pre-v2.9.3a ongoing games

Older unsanctioned admin matches that were already started under v2.9.3 may have accumulated career evidence. **The upgrade does not retroactively relabel them**. Stop/cancel these existing games (which safely reverses their own recoverable per-ball career evidence) and start a new practice match. Existing *completed* game results require explicit administrator review/correction; v2.9.3a never silently removes recorded achievements.

## Database and deployment

No database schema migration is required. Back up `data/gutter_saints.db` before updating. The full build retains all production artwork including the three corrected transparent character sprites. Keep the bot's database outside any source replacement.
