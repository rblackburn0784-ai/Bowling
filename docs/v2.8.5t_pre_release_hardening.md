# Gutter Saints Bowling — v2.8.5t Pre-Release Integration & Visual Hardening

## Scope
Built on v2.8.5s (`main` commit `77ba3e8`). No physics RNG or scoring changes, no broadcast layout or GIF-timing changes.

### Fixed
1. **Overhead view pin formation:** regulation 4–3–2–1 with rear 7–8–9–10, middle 4–5–6, front 2–3 and nearest bowler pin 1. Existing 5–3–2 locator marks are detected and healed **in memory** when the supplied overhead photo is loaded. The original PNG is not modified. An unmarked regulation plate remains recommended.
2. **Fixture completion:** regulation game results are now tied to their scheduled fixture, best-of series ledger, standings and bracket progression. Draws permitted in round-robin; tied eliminations use recorded sudden-death roll-off without changing tenpin scores.
3. **True atomic completion:** game/results/career/XP/competition/legacy bracket/finalization record all commit together or roll back together, with stable `session_uid` retry behaviour and `fixture_games(game_id)` uniqueness.
4. **Legacy tournament safety:** starting an active/completed tournament no longer replaces previous results. Manual entry rejects illegal/negative scores, already finished matches and non-active tournaments.
5. **Friendly XP:** exhibition rewards now accrue in `exhibition_rewards.cosmetic_xp`, never the ranking XP column. Previously earned friendly XP cannot be reliably distinguished from historical normal XP and is not automatically subtracted.
6. **Recovery:** snapshot deserialization no longer modifies its input; the SQLite backup operation uses its online backup API (WAL-safe) and runs `PRAGMA quick_check` on the backup.
7. **Fallback graphics:** pins now progressively fall during impact, instead of showing the leave immediately.
8. **Pre-release checks:** CI now runs all `test_*.py` tests; startup logs missing/invalid artwork, optional `REQUIRE_PRODUCTION_ART=1` blocks incomplete installs. Stale generated lane cards are purged after 14 days.

- `assets/pins/overhead/pin_1.png` through `pin_10.png` and overhead fall sprites.

- `assets/sprites/the_dude/{1..5}.png`, `assets/sprites/jesus/{1..5}.png` (optional `cheer.png`).

`python -c "from services.asset_validation import validate_broadcast_assets; print(validate_broadcast_assets())"` checks them without connecting to Discord. For final deployment, set `REQUIRE_PRODUCTION_ART=1`.

For a **clean overhead image**, the best result is a plate **without prepainted pin circles**. The in-memory compatibility treatment is only a mitigation for the old photograph's decorative 5–3–2 circles.

### Database upgrade
Automatic, additive migration creates `exhibition_rewards`, unique `ix_fixture_game_id` and `fixture_games.rolloff_json`. It does not remove any game or overwrite existing bracket data. **Back up** `data/gutter_saints.db` before updating; keep the existing `data/` directory.

### Test limitations
Local test runtime lacks `discord.py`; standalone SQL/engine/render suites are executable here. Discord interaction checks and real PNG visual alignment require a configured staging server with the assets present. CI installs dependencies and runs full discovery on Python 3.13.

### Release gate
Do not call v2.9.0 production-ready until the actual 941×1672 and 1254×1254 plates are installed, fixture/game recovery is exercised in a test Discord guild, and CI is green for this revision.
